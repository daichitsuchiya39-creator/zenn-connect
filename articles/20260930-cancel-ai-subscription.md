# Claudeのサブスクが払えなくなったので、API生活に移行してみることにした話

## はじめに

ある日、気づいてしまった。

Claudeが使えない。

正確には使えないのではない。

**支払いができなかった。**

理由は単純である。

ヘソクリ。

いや違う。

仕事用に使っている個人口座が、見事にショートしていた。

「まあ、数日後に入金すればいいか」

と思った瞬間、別の考えが頭をよぎった。

> そういえば最近、そんなに毎日開発してなくない？

以前は毎日のようにClaude Codeを起動し、

- 新規実装
- リファクタリング
- 技術調査
- ドキュメント作成
- 趣味開発

を延々と繰り返していた。

しかし最近は本業が忙しい。

気付けばAIと会話しない日も珍しくなくなっていた。

そこでふと考えた。

> 月額3,000円。
>
> 本当に元を取れているのだろうか。

そして、その疑問から思わぬ方向へ話が転がっていった。

---

# サブスク脳の罠

人間はサブスクリプションを契約すると謎の安心感を得る。

- Netflix
- Amazon Prime
- Spotify

みんなそうだ。

契約した瞬間、

> 元を取らなきゃ

という感情が生まれる。

AIサービスも同じである。

しかしAIの場合、少し厄介だ。

なぜなら、

**どれだけ使ったかが見えにくい。**

例えばClaude Proを契約していると、

```text
今日は100万トークン使った

今日は10万トークンしか使っていない
```

という感覚がない。

使っても使わなくても料金は同じ。

だから利用効率を考えなくなる。

---

# APIは怖い

もちろん私もAPIは以前から使っていた。

ただし補助的な利用だ。

なぜなら、インターネットにはこんな記事が溢れているからである。

> 一晩放置したら数万円請求された

> エージェントに全部任せたら月末に気絶した

AI界隈では定期的に、

**「気付いたら家賃並みの請求が来ていた選手権」**

が開催されているように見える。

そのため私の頭の中では長らく、

```text
サブスク = 安全

API = 危険
```

という図式が成立していた。

---

# しかし冷静に考えた

ここで改めて計算してみた。

API料金は基本的に、

```text
入力トークン
+
出力トークン
=
利用料金
```

で決まる。

つまり、

**計算できる。**

むしろサブスクより分かりやすい。

そして最近の自分の利用状況を思い返してみる。

昔の私。

```text
朝：設計
昼：調査
夜：実装
深夜：趣味開発
```

Claudeが同僚だった。

いや、もはや上司だった。

しかし今は、

```text
調査を少し
コード修正を少し
レビューを少し
```

程度である。

明らかに利用量は減っている。

すると、

> 今の自分に本当に定額契約が必要なのか？

という疑問が出てくる。

---

# 実はAPIの方が安心かもしれない

ここで認識がひっくり返った。

APIには上限設定がある。

例えば、

```text
今月の利用上限

1,000円
```

と決めることができる。

つまり、

**プリペイドカードを買う感覚**

なのである。

---

# サブスクは食べ放題、APIはプリペイドカード

サブスクは食べ放題だ。

元を取ろうとして無理に食べる。

お腹が空いていなくても、

> せっかく契約しているし

という気持ちになる。

一方でAPIは違う。

```text
今月は忙しい
↓
1,000円だけ使う

今月は開発合宿する
↓
5,000円まで使う
```

という調整が可能だ。

むしろ、

> 今月はいくらまでAIに使うか

を自分で決められる。

これは思った以上に大きい。

---

# 「無制限」の安心より「予算管理」の安心

昔の私は、

```text
サブスク = 安心
API = 危険
```

だと思っていた。

しかし今はむしろ、

```text
サブスク = 利用量が見えない

API = 利用量が見える
```

だと感じている。

もちろん、上限を設定せずに高性能モデルを延々と動かせば危険だ。

しかし、

- 利用額上限を設定する
- 使用量を監視する
- モデルを使い分ける

という運用をすれば、むしろ管理しやすい。

少なくとも、

「今月はいくら使ったのか分からない」

という事態は避けられる。

---

# 複数モデル時代になるとサブスクはさらに厳しい

そして、ここが今回一番大きな気付きだった。

今のAI開発者は、一つのモデルだけを使うとは限らない。

例えば私の周囲でも、

- Claude
- OpenAI（GPTシリーズ）
- Grok
- Gemini
- DeepSeek
- Qwen
- Mistral

あたりを用途によって使い分けている人が増えている。

設計はClaude。

コード生成はGPT。

軽い調査はGemini。

OSS系はDeepSeek。

最新情報はGrok。

こんな感じだ。

しかし、もしこれらをすべてサブスクリプションで契約したらどうなるだろう。

```text
Claude 3,000円

OpenAI 3,000円

Gemini 3,000円

Grok 3,000円

合計 12,000円
```

実際にはもっと高くなる可能性もある。

そして冷静に考えてみてほしい。

毎月すべてのサービスを同じ熱量で使い倒せるだろうか。

おそらく無理だ。

今月はClaudeばかり使うかもしれない。

来月はGPTばかりかもしれない。

Geminiは数回しか触らないかもしれない。

それなのに全サービスへ固定料金を払い続ける。

これはかなり費用対効果が悪い。

なぜなら、

**人間は一人しかいないからだ。**

もちろん反論はあるだろう。

エージェントを管理するエージェントを作り、

Claudeには設計を担当させ、

GPTには実装を担当させ、

Geminiには調査を担当させ、

Grokには情報収集を担当させる。

そして各サブスクのモデルを24時間フル活用する。

理論上は可能だ。

むしろAIエージェント技術が進化していけば、それは十分に現実的な未来かもしれない。

だが、個人的には少し違和感がある。

なぜなら、

**いつの間にか「エージェントを活用すること」が目的になってしまうからだ。**

本来やりたかったことは、

- プロダクトを作ること
- サービスを改善すること
- 調査を効率化すること
- 学習速度を上げること

だったはずである。

しかし気付けば、

```text
エージェントを管理するエージェント

を管理するエージェント
```

を作り始める。

そして本来の目的が何だったのか分からなくなる。

AIエンジニアあるあるである。

もちろん最終的には、その領域に到達してもよいだろう。

大量のエージェントが自律的に連携し、

それぞれが得意分野を担当する。

そんな「最強のエージェント軍団」を構築する未来も確かに面白い。

ただ、少なくとも今の私にとって重要なのはそこではない。

まずは、

**自分がどのモデルを、どんな場面で、どれだけ価値を感じて使っているのかを理解することだ。**

その点でAPI方式は非常に都合が良い。

サブスクリプションだと、

なんとなくClaudeを使い、

なんとなくGPTを使い、

なんとなくGeminiを試す。

利用量もコストも意識しない。

しかしAPIになると状況は変わる。

```text
このタスクはClaude

このタスクはGPT

これはGemini

これはDeepSeek
```

という判断を自然と行うようになる。

そして、

- なぜそのモデルを選んだのか
- 何が得意なのか
- 何が苦手なのか
- コストに対してどれだけ価値があったのか

を意識するようになる。

結果として、自分自身のモデルに対する解像度が上がる。

単なるコスト削減ではない。

モデルの特徴を理解しながら使い分けることで、

AI活用そのものの学習効率が飛躍的に向上する。

漠然とサブスクリプションを契約している状態よりも、

はるかに能動的な付き合い方ができるようになるのだ。

---

# 制約こそが、最大の自由を生む

考えてみれば、今回のきっかけは極めて情けない。

口座残高不足である。

しかし、その制約があったからこそ、

私は改めて

- 本当に必要なサービスは何か
- どのモデルが何に向いているのか
- どれくらいコストをかけるべきなのか

を考えるようになった。

もし何の制約もなければ、

なんとなくサブスクを継続し、

なんとなく使い続けていたかもしれない。

だが、予算という制約が生まれたことで、

逆にモデル選択の自由度は高まった。

Claudeだけではない。

GPTも使える。

Geminiも使える。

Grokも使える。

必要に応じて他のモデルも試せる。

しかも、その都度最適なものを選択できる。

そう考えると、

今回失ったのはサブスクの安心感だけで、

得たものの方がずっと多い気がしている。

結局のところ、

> 制約こそが、最大の自由を生む。

AIとの付き合い方も、案外同じなのかもしれない。

---

# まとめ

Claudeの支払いができなくなった。

普通なら猛省する場面である。

しかし結果的には、自分のAI利用方法を見直すきっかけになった。

調べてみると、

- 最近は利用頻度が下がっている
- APIには上限設定がある
- 利用額が可視化できる
- 複数モデルを柔軟に使い分けられる
- モデルごとの特性を深く理解できる

というメリットが見えてきた。

そして何より、

複数のAIモデルが乱立する現在、

すべてのサービスをサブスクで契約して元を取るのは現実的ではない。

Claudeも使いたい。

GPTも使いたい。

Geminiも使いたい。

Grokも試したい。

でも、人間は一人しかいない。

だから当面は、

**「必要な時に必要なモデルを呼び出すAPI生活」**

を試してみようと思う。

もちろん来月、

趣味開発熱が再燃してClaude Codeを毎日ぶん回し始めたら話は別だ。

その時は何事もなかったかのようにサブスクへ戻るだろう。

AI開発者とは、

技術的合理性と感情的浪費の間を永遠にさまよう生き物なのである。🚀
